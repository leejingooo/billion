# T 보정 · 독립 추가 자금 · 통합 주문

PR #9의 체결 수량 기반 T 판정을 사용한다. 기존 거래를 수정 후 가상 거래로 재작성하지 않는다. 실제 입금/주문 전송 기능은 없다.

## T 보정

무한매수법의 선택한 계좌에서 **현재 사이클 T 보정 미리보기**를 누른다.

- 각 거래의 `prevSnapshot`은 당시 실제 주문 예산이다. 이를 사용해 체결 수량의 매수분을 판정한다. 수정된 T로 과거 주문을 새로 만들어 비교하지 않는다.
- 매수 증가분과 실제 매도 이벤트의 T 곱셈만 순서대로 누적한다. 같은 날짜의 거래도 저장 순서를 보존한다.
- 시작 T=0/보유 0부터의 완전한 일반모드 이력, 거래와 잔고의 연결을 검증한다. 리버스/수동 보정/불완전 이력/모드 전환 영향은 자동 보정에서 제외한다.
- PR #9의 정수 수량 판정은 원문에 명시된 별도 공식이 아니라 사용자가 요청한 구현 판단이다. 판정 불가능한 거래는 사용자가 확인해야 한다.
- 확인 후 적용하면 현재 T와 감사 기록만 추가한다. 주식 수·평단·현금·실현손익·과거 거래는 동일하다. 자산 그래프에서는 보정 기록을 가격 관측값으로 취급하지 않는다.
- 미리보기 뒤 상태가 바뀌면 적용을 차단한다. 같은 사이클 중복 보정도 차단한다.
- 계좌 설정의 **마지막 하루 기록 되돌리기**로 즉시 보정을 취소할 수 있다. 보정 이후 매매를 추가했다면 되돌리기는 가장 최근 기록부터 순차 적용한다.

사용자가 제공한 11건의 원본 체결 fixture에서는 T=4.09375 → 3.53125, 보유 53주와 잔금 38844.75를 보존한다. 실제 저장 상태가 다르면 이 값을 강제 적용하지 않는다.

## 추가 자금

선택한 기존 계좌에서 **추가 자금으로 독립 전략 시작**을 연다. 기본 입력 금액은 요청한 14600달러이며 수정 가능하다. 종목/분할은 기존 계좌를 따른다.

직전 종가와 그 미국 거래일을 입력하고 원금·첫 주문 미리보기를 확인한다. 기존 전략 잔금에 포함되지 않은 실제 입금 완료된 자금임을 확인한 후 생성한다. 동일 버튼의 연속 클릭은 중복 생성을 막는다.

SOXL 20분할 14600달러는 T=0, 보유 0, 현금 14600, 첫 1회매수금 730달러로 시작한다. 기존 계좌 현금/원금은 차감하거나 가산하지 않는다. 새로운 앱 내 전략 계좌이며 실제 증권계좌 개설이 아니다. 전체 포트폴리오에 새 외부 투입원금으로 계산된다. 통합뷰의 기존 계좌 보관/삭제 기능으로 관리한다.

원문 V4.0 p.1의 독립된 원금 설정과 신규 사이클 구조를 이용한 운영 방식이다. 진행 중 원금을 소급 증액하는 공식이나 두 사이클을 순매수로 합치는 공식은 원문에서 제공하지 않는다. 같은 종목을 한 증권계좌에 두더라도 각 전략의 현금/평단/T는 별도로 유지해야 한다.

## 통합 주문

**통합 주문** 탭에서 운용 중인 전략을 선택한다. 실제로 같은 증권계좌인지 또는 각각 다른 계좌인지 명시적으로 확인하기 전 복사를 막는다.

- 동일 증권계좌로 확인했을 때만 종목/방향/주문유형/가격/시간이 모두 같은 주문 수량을 합산한다.
- 가격이 다르면 별도 행이다. 원래 사다리/매수/매도 가격을 변경하지 않는다.
- 각 행에 원래 전략별 수량을 남긴다. 총수량과 전략별 배분량이 일치한다.
- 같은 종목의 매수 가격이 매도 가격 이상인 구간 및 MOC와 반대 방향 주문은 충돌 표시한다. 상계, 가상 내부거래, 매도가 이동은 하지 않는다. 충돌이 있으면 일괄 복사 차단.
- 기준일 누락/동일 종목의 날짜·종가 불일치/잘못된 상태는 복사 차단. 보정·입금 기록의 날짜는 종가 날짜로 취급하지 않는다.
- 복사 시 조회 이후 잔고가 바뀌거나 계좌가 보관/삭제됐는지 다시 확인한다.
- 체결 후 실제 수량을 원래 전략에 각각 입력해야 한다. 일부 체결의 자동 배분이나 두 전략 원장의 일괄 정산은 제공하지 않는다. 주문 표의 배분은 예정 수량이다.

새 전략의 큰수 매수 가격과 기존 전략의 매도 가격이 겹칠 수 있다. 이 상황에서 한 계좌의 주문 수를 항상 줄이면서 원래 두 전략을 정확히 유지할 수 있다고 보장하지 않는다. 충돌을 해결하려고 주문을 자동 취소하거나 두 전략을 합치지 않는다.

## 검증 및 제한

순수 함수 테스트와 Vite/React 앱 테스트로 실제 체결 fixture, 보정 적용/되돌리기, 미리보기 변경 감지, 새 전략 생성·중복 방지·기존 자금 보존, 합산·충돌·기준일·복사 흐름을 검증한다. npm run gate/build에도 포함된다. 실제 증권계좌나 Supabase 실계정으로 주문/입금하지 않는다.

저장소의 기존 Supabase 드라이버는 로컬 캐시 반영 뒤 비동기 동기화를 수행한다. 이 기능은 기존 저장 방식을 사용하며 서버의 다중 키 트랜잭션이나 다른 기기 사이의 원자적 잠금을 추가하지 않는다. 같은 전략의 동시 편집은 피해야 한다.
