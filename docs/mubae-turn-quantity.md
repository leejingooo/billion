# 전반전 T 정수 체결 수량 판정 (2026-10-08)

## 근거와 한계

제공된 라오어 V4.0 원문 p.2는 일반모드 1회매수 +1, 절반매수 +0.5, 쿼터매도 ×0.75를 정의한다. p.3~4의 1회매수금은 잔금/(분할수−T)이다. p.5~6은 전반전 별지점/평단 매수와 사다리 예시를 제공한다.

원문에는 사다리 1주만 체결되면 +1이라는 규칙, 평단 위 사다리 금지 규칙, 부분체결 및 정수 수량 판정식이 없다. 따라서 아래 판정은 사용자가 요청한 수량 비교를 구현한 것으로 저자의 명시적 공식이라고 주장하지 않는다. 매수액 비율을 연속 T로 환산하지 않는다.

## 이번 변경

- 일반모드 전반전에서 양수 실제 체결 수량을 합산한다. 모두 동일한 가격에 체결된 경우만 자동 수량 비교한다.
- 그 가격으로 1회매수금을 나눈 정수 내림 수량과 같으면 +1, 절반 금액의 정수 내림 수량과 같으면 +0.5.
- 주문가 기준 내림으로 별지점 주문 수량이 위 절반 수량보다 적을 수 있다. 이때 평단 위에서 실제 생성된 매수 주문의 체결예상 수량과 일치하고 전체분보다 작으며 평단 주문은 체결되지 않는 경우 +0.5.
- 위 기준에 맞지 않거나 여러 체결가가 있으면 자동 확정 차단. 사용자가 +0.5/+1을 확인하면 선택과 이전 상태를 이력에 남긴다. 입력 변경 시 확인을 초기화한다.
- 실제 체결 수량이 우연히 정상 절반 수량과 같은 부분체결인지는 수량만으로 구분할 수 없다. 실제 체결 확인 책임을 대체하지 않으며 모든 예외가 원문으로 해결됐다고 주장하지 않는다.
- 첫매수, 후반전, 매도, 리버스 로직은 변경하지 않는다. getOrders/사다리 가격/체결 시뮬레이터도 변경하지 않는다.

## 검증 및 범위

실제 두 엔진의 함수로 수량·라벨 독립성·원문 p.6 숫자 예시·매도 곱셈·부분체결 확인을 검증한다. React/Vite로 자동 판정, 확정 차단, 확인 저장, 입력 변경 시 확인 초기화를 검증한다. npm run gate/build에서도 이 테스트들이 실패하면 차단한다.

통합 주문 기능, $14,600 증액, 기존 계좌 상태 보정은 이 변경에 포함하지 않는다. LOCKED 수정은 사용자가 이번 오류에 한해 승인한 범위이다.
